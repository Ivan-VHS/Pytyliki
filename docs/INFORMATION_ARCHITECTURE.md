# Pytyliki documentation information architecture

[Project README](../README.md) · [Documentation index](README.md)

This is the canonical map for the Pytyliki documentation library. The catalog is derived from the repository tree so each maintained Markdown page has a direct navigation path. Source, tests, schemas and build files are authoritative for implementation status.

## Entry points and authority

- **Project entry:** [README](../README.md) — product purpose, platform scope and build commands.
- **Documentation home:** [docs/README.md](README.md) — key technical references and topic hubs.
- **Feature matrix:** [FEATURES](FEATURES.md) — capability inventory and boundaries.
- **Documentation control:** [DOCUMENTATION_CONTROL](DOCUMENTATION_CONTROL.md) — evidence and publication gates.
- **Authority:** C11 source defines behavior; tests/CI show what was exercised; C ABI/schema files define contracts; CMake defines build targets. Documentation must match these sources.

## Maintenance and review

- Update this map and the relevant cluster hub in the same pull request when documents are added, moved or retired.
- Keep all four README locales aligned on capabilities, command lines, platforms, maturity and licensing.
- Preserve read-only hardware behavior and static source-review boundaries in every integration guide.
- Keep ABI and JSON format changes versioned; document breaking changes and migration paths.
- Link performance evidence to its host, compiler, flags, workload, sample count and method.
- Verify every changed path and build command in a clean checkout before release.
- Use the canonical [DAK documentation standard](https://github.com/Ivan-VHS/DAK/blob/main/docs/UNIFIED_DOCUMENTATION_STANDARD.md) for the shared 50-point publication checklist.
