# Reaper language integration

Pytyliki remains a C11 processor-systems workstation. Reaper is an optional, host-side orchestration and analysis language; it does not replace real-time DSP, CPU discovery, C ABI primitives or bounded native processing.

## Reaper programs

### Native ABI metrics

`automation/reaper/processor_metrics.rpr` opens the explicitly built Pytyliki C ABI v1 library, calls norm/dot/distance/orthogonality operations through Reaper's typed bridge, discovers the 18-entry native plugin catalogue without loading plugins, resolves one metadata descriptor, checks the returned values, and writes `build/reaper-metrics-report.json`.

### Processor Intelligence

`automation/reaper/processor_intelligence.rpr` imports the Reaper-owned `stdlib/processor_intelligence.rpr` source module from the pinned Reaper checkout in `_deps/Reaper`. It consumes the versioned native ABI report, then validates deterministic processor-action fixtures and produces `build/processor-intelligence-report.json`.

The Processor Intelligence report demonstrates state transitions and action counters, pulse/cadence analysis, logical slow-motion schedules, memory-budget validation, processor-package topology, graph reduction, checkpoint caching, table export, a tray-ready status record and read-only hardware policy. The processor-action records and CPU package values in this script are explicitly marked as deterministic fixtures, not live readings.

## Build and run from the repository root

```sh
cmake -S . -B build -DBUILD_TESTING=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel --target pytyliki_ffi

PYTHONPATH=/path/to/Reaper python -m reaper --check automation/reaper/processor_metrics.rpr
PYTHONPATH=/path/to/Reaper python -m reaper --engine vm --allow-native-ffi automation/reaper/processor_metrics.rpr

PYTHONPATH=/path/to/Reaper python -m reaper --check automation/reaper/processor_intelligence.rpr
PYTHONPATH=/path/to/Reaper python -m reaper --engine vm automation/reaper/processor_intelligence.rpr
```

The metrics example expects the Linux shared-library path `build/libpytyliki_ffi.so`. On Windows, use the CMake-generated DLL path in the same explicit way; do not add a PATH or implicit search fallback. The Processor Intelligence script imports the language module from the checked-out Reaper source tree and reads the report generated by the first program.

## Integration contract

- Reaper owns source-level orchestration, deterministic state modeling, structured reporting and bounded collection transforms.
- The versioned Reaper module is the language-level owner of processor-state/action contracts; it does not claim that equivalent native compiler lowering is complete.
- Pytyliki owns actual processor discovery, usable ISA checks, bounded CPU/memory measurements, Embedded C profile data and the C ABI v1 implementation.
- The existing ABI script passes finite, small vectors and scalar tolerances to the native ABI. The Processor Intelligence report includes selected results from that real native call.
- Processor action traces and CPU package topology in the integration fixture are synthetic and carry `fixture`/`simulated` provenance. They are not derived from the host CPU and must not be shown as live telemetry.
- The native library is loaded only with the explicit `--allow-native-ffi` opt-in and a path resolved relative to the script.
- `pytyliki_plugin_catalog` and `pytyliki_plugin_info` expose bounded metadata only; plugin code is not loaded or invoked.
- There is no automatic network access, executable lookup, plugin loading or audio-callback dependency.
- Reaper's reference runtime and bytecode VM are used by the existing integration workflow; Reaper's C17 compiler remains a separate, partial compiler track.

## Safety boundaries

- Processor and hardware discovery remain read-only. No scheduler, affinity, clock, voltage, firmware, BIOS/UEFI, driver or device-register writes are performed.
- Reaper's slow-motion operation scales logical replay ticks; it does not throttle a physical CPU.
- The tray snapshot is a small data record for a host UI; it is not a resident system-tray application.
- Memory and Embedded C budgets are accounting/validation outputs. They do not allocate physical RAM, map MCU addresses or flash firmware.
- Hardware policy returns an observation-only or simulation-plan result. It does not open a device adapter or execute MMIO.
- The workflow pins Reaper to a reviewed commit. Updates to that pin are explicit and should be made together with the Reaper language module changes.

The integration workflow builds the real C library, executes both `.rpr` programs, and verifies each versioned JSON report.
