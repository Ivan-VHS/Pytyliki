# DAKStory

DAKStory — бережный контур непрерывного улучшения приложения. Он регулярно собирает проверяемые сигналы о качестве, превращает их в понятный список следующих шагов и не подменяет инженерное решение автоматическим переписыванием исходников.

## Восемь направлений качества

1. **Security & Privacy** — защита данных, границы доверия и минимальные права автоматизации.
2. **Reliability** — синтаксическая целостность, тесты, сборка и регрессионная устойчивость.
3. **Supply Chain** — зависимости, фиксация версий GitHub Actions и прозрачность сборки.
4. **Accessibility** — доступность управления, фокуса, контраста и экранных дикторов.
5. **Performance** — измеряемые время выполнения, память и нагрузка.
6. **Compatibility** — подтверждённая работа на заявленных ОС, архитектурах и версиях runtime.
7. **Maintainability** — небольшие функции, говорящие имена, прямой поток, guard clauses и отсутствие лишних абстракций.
8. **Product Quality** — понятная документация, предсказуемые сценарии, воспроизводимость и аккуратные ошибки.

## Что выполняется автоматически

- обнаружение основных технологических стеков и тестовых файлов;
- разбор Python AST и синтаксическая проверка JSON;
- поиск крупных исходных файлов как повода для ревью, а не как автоматического дефекта;
- проверка наличия README, SECURITY.md, лицензии и CI;
- просмотр GitHub Actions на незакреплённые SHA и чрезмерные права;
- формирование JSON-отчёта и Markdown-сводки с приоритетными рекомендациями;
- самостоятельный self-test механизма в изолированной временной папке.

DAKStory не запускает проектные команды, не устанавливает и не обновляет зависимости, не обращается к сети, не читает содержимое потенциальных секретов и не изменяет прикладные исходники.

## Использование

```bash
python scripts/dakstory.py self-test
python scripts/dakstory.py audit
python scripts/dakstory.py audit --json .dakstory/reports/latest.json --markdown .dakstory/reports/latest.md
python scripts/dakstory.py safe-fix
```

Команда safe-fix создаёт корневой .editorconfig только при его отсутствии. Существующая пользовательская конфигурация никогда не перезаписывается. Каталог .dakstory/reports исключён из Git.

Проверка в CI запускается при push в main, pull request, вручную и по недельному расписанию. Отчёт публикуется в GitHub Actions job summary. Ошибки Python/JSON делают проверку неуспешной; рекомендации и необходимость ручного тестирования остаются видимыми, но не блокируют сборку автоматически.

## Нормативные ориентиры

- **OWASP ASVS 5.0.0** — стабильная основа проверки безопасности веб-приложений и сервисов; применяется там, где релевантен профиль приложения.
- **WCAG 2.2 / ISO/IEC 40500:2025** — ориентир доступности пользовательских интерфейсов. Для нативных desktop-приложений дополнительно нужны платформенные проверки.
- **NIST SP 800-218 v1.1** — опубликованный базовый Secure Software Development Framework. SP 800-218 Rev. 1 v1.2 учитывается как проект редакции, а не как утверждённый стандарт.
- **GitHub Actions security guidance** — минимальные token permissions, закрепление сторонних actions полными commit SHA и отказ от лишних секретов.

Стандарты применяются по области действия. Статический отчёт DAKStory не является аудитом, сертификатом соответствия или обещанием отсутствия уязвимостей.

## Человечный стиль кода

DAKStory поощряет естественный, авторский код: осмысленные имена, короткие функции с одной задачей, раннюю проверку входных данных, понятные сообщения об ошибках и комментарии только там, где они объясняют решение. Улучшение читаемости не должно ломать совместимость или превращать простой код в декоративную систему абстракций.
